## Команды

```bash
npm test                                      # весь прогон jest
npm run test:watch                            # jest в watch-режиме
npm run typecheck                             # tsc --noEmit
npm start                                     # запустить черновой сценарий index.ts через tsx
npx jest src/text/spec.test.ts                # один файл
npx jest -t "M3"                              # один закон/тест по имени
```

Две ловушки запуска:

- `node index.ts` **не работает**: в `package.json` стоит `"type": "commonjs"`, а файл использует
  ESM-импорты; вдобавок `ItemType` и `Bias` — это `enum`, для которых нужен
  `--experimental-transform-types`. Запускать через `tsx`.
- `npx tsc <файлы>` с именами файлов в аргументах **игнорирует** `tsconfig.json` и требует
  `--ignoreConfig` плюс явные `--module commonjs --target esnext --esModuleInterop`.
  Для проверки всего проекта использовать `npx tsc --noEmit` без аргументов.

## Что это за код

Ядро — персистентное B-дерево (SumTree / rope). Текст лежит чанками в листьях; каждый узел
хранит моноидальное саммари своего поддерева, поэтому позиционные запросы стоят `O(log n)`,
а не `O(n)`.

Код разделён на два слоя, и это разделение — проверяемое правило, а не соглашение:

- **`src/sumtree/`** — обобщённое дерево по `T` (значение в листе) и `S` (саммари). Про
  строки не знает ничего и **не имеет права импортировать из `src/text/`**; за этим следит
  `layering.test.ts`.
- **`src/text/`** — конкретизация для текста: `sumTreeSpec`, `TextSummary`, `chunkify`,
  размерности.

У каждого слоя есть `index.ts` — публичная поверхность. `join`, `pack`, `joinLeaves`,
`collapseItems` наружу не выходят.

Три точки расширения:

- **`TreeSpec<T, S>`** (`sumtree/spec.ts`, реализация — `text/spec.ts`) — всё, что знает про
  содержимое: моноид над саммари (`default` / `summary` / `combine`) и чанкинг
  (`size` / `concat` / `split` / `maxSize`). Формально `(S, combine, default)` и
  `(T, concat, empty)` — моноиды, а `summary` — гомоморфизм между ними. Именно гомоморфизм
  позволяет вычислить саммари узла из саммарей детей, не заглядывая в текст, — на этом
  держится вся конструкция.
- **`Dimension<S, D>`** (`sumtree/dimension.ts`, реализации — `text/dimensions.ts`) — как
  свернуть саммари в координату, по которой ведётся навигация (`offsetDimension`,
  `pointDimension`). Спуск по дереву корректен, потому что `addSummary` монотонна и
  согласована с `combine`.
- **`Item<T, S>`** (`sumtree/item.ts`) — узлы дерева: интерфейсы `InternalItem` / `LeafItem`
  и классы `Internal` / `Leaf` лежат вместе.

Операции — в `sumtree/ops.ts`: публичные `build`, `merge`, `slice`, `seek`, `splitAt`;
приватные `join`, `pack`, `joinLeaves`, `collapseItems`.

### Центральный алгоритм

`join` возвращает **один или два узла** высоты `max(a, b)`. Двойка означает переполнение на
этом уровне, и её поглощает вызывающий через `pack`. За счёт этого баланс держится без
отдельного прохода перебалансировки, а `merge` деревьев разной высоты вклеивает низкое в
спину высокого, а не строит новый корень.

Операции персистентны: операнды не мутируются, перестраивается только изменённый путь,
остальные поддеревья разделяются по ссылке.

### Инварианты

Нигде в коде не записаны — восстанавливаются чтением, поэтому держать в голове:

- все листья на одной глубине;
- у внутреннего узла от 1 до `TREE_BASE` детей (0 — только у корня пустого дерева);
- `node.height === child.height + 1`, у листа высота 0;
- саммари узла равно свёртке саммарей его детей через `combine`;
- размер листа в `[CHUNK_MIN, CHUNK_MAX]`, последний лист может быть короче;
- `CHUNK_MAX = 2 · CHUNK_MIN` — несущее соотношение: только при нём разрез переполненного
  чанка пополам оставляет обе половины в границах.

## Законы и их идентификаторы

`docs/draft/spec.md` — глоссарий и спецификация `TreeSpec`. У каждого закона есть
идентификатор: `M1`–`M4` (моноид), `C1`–`C6` (чанкинг). Имя теста начинается с этого
идентификатора, поэтому `npx jest -t "M3"` запускает ровно нужный закон, а `grep -rn "C3"`
находит и формулировку, и тест.

Соглашение: у закона в таблице либо ссылка на тест, либо явное `нет` — пустых клеток не
бывает. Сейчас все `C`-законы помечены `нет`; это видимый долг, а не упущение.

В `text/spec.test.ts` намеренно разделены два `describe`: законы интерфейса `TreeSpec` и
свойства конкретной реализации `sumTreeSpec`. Не смешивать — другая спека вправе вести себя
иначе.

## Текущее состояние

Базовая линия прогона: **21 тест проходит, 2 падают**, `tsc` чист, `npm start` доходит до
конца. Два падения — в `sumtree/ops.test.ts`, они прежние и ожидаемые, не считать их своей
регрессией.

Что важно знать про эти два теста: они ожидают лист из одного символа (`'1'`, `'4'`) —
ожидания подогнаны под старую сломанную версию `split`, которая возвращала два символа
хвоста. `split` с тех пор исправлен, поэтому тесты подлежат удалению, а не починке.

**Корректность `build` / `merge` / `slice` / `seek` не подтверждена.** Все четыре
переписывались, но оракульных и property-тестов нет, а те, что есть, проверяют моноид спеки,
а не операции над деревом. Из C-законов (`C1`–`C6`) не проверен ни один. Перед правками
в `sumtree/ops.ts` стоит сначала поставить оракул на плоской строке: `SumTree` не делает
ничего, чего не делает `String`, поэтому `textOf(slice(t, f, to)) === s.slice(f, to)` —
проверяемо и не подгоняется под баг.

Известный незакрытый пробел: `split` режет по индексу UTF-16 и может разорвать суррогатную
пару. Отдельного закона на это пока нет.

При правке кода **перечитывать файл, а не полагаться на прочитанное ранее**: `split` в этом
проекте однажды был восстановлен в сломанное состояние именно так.

## Ловушки

- **`TREE_BASE` и `CHUNK_MAX` — разные понятия**, численно совпадающие (оба `4`). Первое —
  арность дерева (`sumtree/constants.ts`), второе — размер содержимого листа
  (`text/chunk.ts`). Однажды `pack` из-за этой путаницы резал узлы по размеру чанка. Теперь
  они в разных слоях, и `sumtree/` до `CHUNK_MAX` не дотянется: сравнение идёт со
  `spec.maxSize`.
- **Кириллические гомоглифы.** В коде уже жил метод `сompare` с кириллической `с`: он
  компилировался, но не находился поиском по `compare`. При правке `dimension.ts` и `ops.ts`
  проверять идентификаторы.
- **`strict` включён и проходит чисто**, но ловит здесь меньше, чем ожидаешь: сравнение
  обобщённых `D` оператором `<` TypeScript разрешает и в строгом режиме. Реально недостающий
  флаг — `noUncheckedIndexedAccess`: в `sumtree/ops.ts` он показывает шесть мест, из них
  настоящие — строки 137 и 141 (`seek`), 86-87 (`slice`), 174 (`collapseItems`). Включать
  вместе с починкой этих функций, не раньше: сам по себе он потребует правок логики.
- `prettier` настроен (`.prettierrc`), но по коду ещё не прогонялся: первый запуск нормализует
  кавычки — в `ops.ts` они двойные, в тестах одинарные.
